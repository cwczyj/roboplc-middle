# 测试指南

> 本指南说明如何测试 RoboPLC 系统，包括单元测试、集成测试和端到端测试。

## 🧪 测试结构

```
src/
└── workers/
    ├── manager.rs           # 设备管理器（消息路由）
    ├── rpc_worker.rs        # JSON-RPC 服务（异步架构）
    ├── http_worker.rs       # HTTP API 服务
    ├── modbus/
    │   ├── worker.rs        # Modbus Worker（每个设备一个）
    │   ├── client.rs        # Modbus TCP 客户端
    │   ├── operations.rs    # 寄存器操作
    │   ├── parsing.rs       # 信号组编码/解码

    ├── config_loader.rs     # 配置热加载（文件监控）
```

## 🏗️ Worker 架构

```
┌──────────────┐     ┌──────────────┐     ┌──────────┐
│  RpcWorker   │────▶│   Manager    │◀────│HttpWorker│
│  (JSON-RPC)  │     │  (消息路由)   │     │(HTTP API)│
└──────────────┘     └──────┬───────┘     └──────────┘
                              │
                       ┌──────┴───────┐
                       ▼              ▼
                ┌──────────┐    ┌──────────┐
                │ModbusWorker│   │ModbusWorker│ (每个设备一个)
                │ (设备1)   │    │ (设备2)   │
                └──────────┘    └──────────┘

┌──────────────┐     ┌──────────────┐
│ConfigLoader  │     │LatencyMonitor│
│(配置热重载)   │     │(延迟监控)    │
└──────────────┘     └──────────────┘
```

**架构演进说明：**
- RpcWorker 现在使用异步架构（tokio + mpsc/oneshot 通道）
- DeviceManager 不再路由 DeviceControl/Response 消息
- ModbusWorker 直接使用 respond_to 通道响应 RpcWorker

```rust
#[test]
fn test_rpc_to_modbus_roundtrip() {
    // 启动 Mock Modbus 服务器
    let mock_server = MockModbusServer::start(MockModbusConfig::default()).unwrap();
    mock_server.set_holding_register(100, 42);

    // 创建测试配置
    let config_file = create_test_config(18882, 18883, mock_server.port());
    let config = Config::from_file(config_file.path()).expect("Failed to load config");

    // 创建 DeviceControl 消息（模拟 RPC worker）
    let control_message = Message::DeviceControl {
        device_id: "test-plc".to_string(),
        operation: Operation::ReadSignalGroup,
        params: json!({ "group_name": "sensor_data" }),
        correlation_id: test_correlation_id,
        respond_to: None,
    };

    // 验证消息内容
    if let Message::DeviceControl { device_id, operation, params, correlation_id, .. } = control_message {
        assert_eq!(device_id, "test-plc");
        assert!(matches!(operation, Operation::ReadSignalGroup));
        
        // 创建 DeviceResponse 消息（模拟 Modbus worker 响应）
        let response_message = Message::DeviceResponse {
            device_id: device_id.clone(),
            success: true,
            data: json!({ "values": [42], "latency_us": 500 }),
            error: None,
            correlation_id,
        };
    }

    mock_server.stop();
}
```

```rust
async fn test_mpsc_channel_device_control() {
    let (tx, mut rx) = mpsc::channel(100);

    let (response_tx, _response_rx) = oneshot::channel();
    let request = DeviceControlRequest {
        device_id: "test-device".to_string(),
        operation: Operation::GetStatus,
        params: serde_json::json!({}),
        correlation_id: 1,
        respond_to: response_tx,
    };

    tx.send(request).await.unwrap();
    let received = rx.recv().await.unwrap();
    assert_eq!(received.device_id, "test-device");
}

#[tokio::test]
async fn test_timeout_handling_slow_response() {
    let (tx, rx) = oneshot::channel::<DeviceResponseData>();

    // 模拟慢处理
    let handle = tokio::spawn(async move {
        sleep(Duration::from_millis(200)).await;
        let _ = tx.send((true, serde_json::json!({}), None));
    });

    // 50ms 后应该超时
    let result = timeout(Duration::from_millis(50), rx).await;
```

**并发请求测试：**
```rust
#[tokio::test]
async fn test_concurrent_requests() {
    let (tx, mut rx) = mpsc::channel(1000);
    let message_count = 100;

    let sender = tokio::spawn(async move {
        for i in 0..message_count {
            let (response_tx, _) = oneshot::channel();
            let request = DeviceControlRequest {
                device_id: format!("device-{}", i),
                operation: Operation::GetStatus,
                params: serde_json::json!({}),
                correlation_id: i as u64,
                respond_to: response_tx,
            };
            tx.send(request).await.unwrap();
        }
    });

    // 测量接收时间
    let start = Instant::now();
    let mut received = 0;
    while received < message_count {
        if let Ok(Some(_)) = timeout(Duration::from_millis(100), rx.recv()).await {
            received += 1;
        }
    }
    let elapsed = start.elapsed();

    println!("Channel throughput: {} messages in {:?}", message_count, elapsed);
}
```

### 4. Mock Modbus 服务器测试

**目的：** 提供 Modbus TCP 设备的 Mock 实现，无需真实硬件

### 什么是 Mock Modbus 服务器？

Mock Modbus 服务器是一个完整的 Modbus TCP 协议模拟器，用于：
- 测试 ModbusWorker 而无需真实 PLC 设备
- 模拟各种网络和协议场景（延迟、超时、异常）
- 控制寄存器值以验证读写操作
- 自动分配端口，避免测试冲突

### 基本使用

**启动 Mock 服务器：**
```rust
use roboplc_middleware::tests::mock_modbus::{MockModbusServer, MockModbusConfig};

// 启动 Mock 服务器（自动分配端口）
let server = MockModbusServer::start(MockModbusConfig::default()).unwrap();
println!("Server running on port {}", server.port());

// 配置测试寄存器
server.set_holding_register(100, 42);
server.set_holding_registers(100, &[10, 20, 30]); // 批量设置

// 读取寄存器值
assert_eq!(server.get_holding_register(100), Some(42));

// 测试完成后停止服务器
server.stop();
```

### 测试 ModbusWorker 完整示例

```rust
#[test]
fn test_modbus_worker_with_mock_server() {
    // 1. 启动 Mock Modbus 服务器
    let mock_server = MockModbusServer::start(MockModbusConfig::default()).unwrap();
    let modbus_port = mock_server.port();
    
    // 2. 预设一些测试数据
    mock_server.set_holding_register(100, 42);
    mock_server.set_holding_register(101, 100);
    mock_server.set_holding_registers(200, &[1, 2, 3, 4, 5]);
    
    // 3. 创建测试配置，指向 Mock 服务器
    let config_content = format!(
        r#"
[server]
rpc_port = 8888
http_port = 8889

[logging]
level = "warn"

[[devices]]
id = "test-plc"
type = "plc"
address = "127.0.0.1"
port = {}
unit_id = 1
addressing_mode = "zero_based"
byte_order = "big_endian"
tcp_nodelay = true
max_concurrent_ops = 3
heartbeat_interval_sec = 30
"#,
        modbus_port
    );
    
    let temp_file = tempfile::NamedTempFile::new().unwrap();
    std::fs::write(temp_file.path(), config_content).unwrap();
    
    // 4. 加载配置并创建 ModbusWorker
    let config = Config::from_file(temp_file.path()).unwrap();
    let worker = ModbusWorker::new(config.devices[0].clone());
    
    // 5. 验证 Worker 配置正确
    assert_eq!(worker.device.id, "test-plc");
    assert_eq!(worker.device.port, modbus_port);
    
    // 6. 清理
    mock_server.stop();
}
```

### 高级配置和场景模拟

**1. 模拟网络延迟**
```rust
let config = MockModbusConfig {
    port: 0,
    unit_id: 255,
    response_delay_ms: 100,  // 模拟 100ms 延迟
    accept_connections: true,
    drop_after_requests: None,
};

let server = MockModbusServer::start(config).unwrap();
// 所有响应都会有 100ms 延迟
```

**2. 模拟连接断开**
```rust
let config = MockModbusConfig {
    port: 0,
    unit_id: 255,
    response_delay_ms: 0,
    accept_connections: true,
    drop_after_requests: Some(5), // 5 个请求后断开连接
};

let server = MockModbusServer::start(config).unwrap();
// 可以测试连接断开后 ModbusWorker 的重连逻辑
```

**3. 模拟异常响应**
```rust
let server = MockModbusServer::start(MockModbusConfig::default()).unwrap();

// 下一个请求会返回异常
server.fail_next_request();

// 测试 ModbusWorker 的错误处理
```

### Mock 服务器 API 参考

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `start(config)` | `MockModbusConfig` | `Result<MockModbusServer>` | 启动服务器 |
| `port()` | - | `u16` | 获取监听端口 |
| `address()` | - | `String` | 获取连接地址 |
| `stop()` | - | - | 停止服务器 |
| `set_holding_register(addr, value)` | `(u16, u16)` | - | 设置保持寄存器 |
| `set_holding_registers(start, values)` | `(u16, &[u16])` | - | 批量设置保持寄存器 |
| `get_holding_register(addr)` | `u16` | `Option<u16>` | 获取保持寄存器值 |
| `set_input_register(addr, value)` | `(u16, u16)` | - | 设置输入寄存器 |
| `set_coil(addr, value)` | `(u16, bool)` | - | 设置线圈 |
| `set_discrete_input(addr, value)` | `(u16, bool)` | - | 设置离散输入 |
| `request_count()` | - | `usize` | 获取请求计数 |
| `fail_next_request()` | - | - | 下一个请求返回异常 |
| `reset()` | - | - | 重置所有状态 |

**支持的 Modbus 功能码：**
- `0x01` - Read Coils
- `0x02` - Read Discrete Inputs
- `0x03` - Read Holding Registers
- `0x04` - Read Input Registers
- `0x05` - Write Single Coil
- `0x06` - Write Single Register
- `0x10` - Write Multiple Registers
- `0x08` - Diagnostics

**文件位置：**
- `tests/mock_modbus.rs` - 700 行完整实现
- 在 `e2e_tests.rs` 中被广泛使用

## 🎯 测试最佳实践

### 1. 测试隔离
- 每个测试独立运行，不互相干扰
- 使用 `tempfile::NamedTempFile` 创建临时配置文件（自动删除）
- 测试后清理 Mock 资源

### 2. 端口管理
- E2E 测试使用 `portpicker::pick_unused_port()` 动态分配端口
- 避免硬编码端口，防止端口冲突
- Mock Modbus 服务器支持自动端口分配（配置 `port: 0`）

### 3. 配置辅助函数
使用 `create_test_config` 等辅助函数创建测试配置：

```rust
fn create_test_config(custom_ports: Option<(u16, u16)>) -> tempfile::NamedTempFile {
    let (rpc_port, http_port) = custom_ports.unwrap_or((8888, 8889));
    // 写入 TOML 配置到临时文件
    // 返回 NamedTempFile（drop 时自动删除）
}
```

### 4. 错误处理和断言
- 使用 `assert!()`、`assert_eq!()`、`assert_ne!()` 进行断言
- 使用 `.expect()` 提供清晰的错误消息
- 使用 `.unwrap()` 只在测试安全时使用

### 5. Mock 服务器使用
- Mock Modbus 服务器支持完整的 Modbus TCP 协议
- 可以模拟各种场景：延迟、超时、异常响应
- 测试完成后调用 `server.stop()` 清理资源

### 6. 异步测试
使用 `#[tokio::test]` 属性标记异步测试：
```rust
#[tokio::test]
async fn test_async_operation() {
    // 异步测试代码
}
```

### 7. 并发测试
测试并发场景时：
```rust

    let mut handles = vec![];
```
