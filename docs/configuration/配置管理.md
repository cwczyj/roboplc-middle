# 配置管理

> RoboPLC 支持配置热更新，无需重启系统即可应用配置更改。

## 🔧 热更新流程

### 触发方式

**配置文件变化** → ConfigLoader 检测 → 通过 Hub 广播 ConfigUpdate

### 更新流程

```
配置文件变化
  │
  ▼
  │
  ├── ConfigLoader 检测到 config.toml 变化
  │
  ├── 读取新配置
  │  │  │
  ├── 对比内容（JSON 序列化后比较）
  │  │  │
  └── 通过 Hub 广播 ConfigUpdate 消息
  │
  │
  ▼
  │
  ├── ConfigUpdater 接收 ConfigUpdate
  │  │  │
  ├── 解析配置 JSON
  │  │  │
  ├── 更新全局 Config 变量
  │  │  ├── 更新 device_states 中的设备状态
  │  │  │  ├── 更新 DeviceManager 的 worker_map
  │  │  │
  └── 必要时通知相关 Worker 重启
```

## 📋 ConfigUpdate 消息

**字段：**
```rust
pub struct ConfigUpdate {
    pub config: String,  // JSON 格式的配置内容
}
```

**用途：**
- 传递完整的新配置（包含 devices 配置）
- ConfigUpdater 可以直接对比新旧配置，决定需要更新的设备
- 使用 JSON 格式便于内容对比

## 🔧 配置更新逻辑

### 1. 配置解析

ConfigLoader 使用 `serde_json::from_str()` 解析配置：
```rust
let new_config: Config = serde_json::from_str(&config_json)?;
```

### 2. 内容对比

ConfigLoader 使用内容对比避免不必要的重载：

```rust
fn reload_config(&mut self) -> Result<Option<(String, Vec<String>)>, Box<dyn std::error::Error>> {
    let new_config = Config::from_file(&self.config_path)?;
    
    let old_value = serde_json::to_value(&self.current_config)?;
    let new_value = serde_json::to_value(&new_config)?;
    let mut changed_paths = Vec::new();
    Self::collect_diff_paths("", &old_value, &new_value, &mut changed_paths);
    
    if changed_paths.is_empty() {
        return Ok(None);  // 无变化，不重载
    }
    
    let config_json = serde_json::to_string(&new_config)?;
    self.current_config = new_config;
    
    Ok(Some((config_json, changed_paths)))
}
```

### 3. 差异检测

遍历新旧配置的差异：

```rust
fn collect_diff_paths(prefix: &str, old: &JsonValue, new: &JsonValue, out: &mut Vec<String>) {
    match (old, new) {
        (JsonValue::Object(old_map), JsonValue::Object(new_map)) => {
            // 比较对象字段
            let keys: BTreeSet<&str> = old_map.keys()
                .map(String::as_str)
                .chain(new_map.keys().map(String::as_str))
                .collect();
            
            for key in keys {
                // 递归比较
            }
        }
        (JsonValue::Array(old_arr), JsonValue::Array(new_arr)) => {
            if old_arr != new_arr {
                out.push(prefix.to_string());
            }
        }
        _ => {
            if old != new {
                out.push(prefix.to_string());
            }
        }
    }
}
```

### 4. 状态更新

#### 更新 device_states

```rust
// 移除的设备：从 device_states 中删除并记录断开
for device_id in removed_devices {
    let mut states = device_states.write();
    states.remove(device_id);
}

// 新增的设备：添加到 device_states 并记录连接状态
for device in added_devices {
    let mut states = device_states.write();
    states.insert(
        device.id.clone(),
        DeviceStatus {
            connected: false,
            last_communication: time::Instant::now(),
            error_count: 0,
            reconnect_count: 0,
        },
    );
}
```

#### 更新 worker_map

如果设备列表变化，需要更新 DeviceManager 的 worker_map：

```rust
// 1. 清空 worker_map
self.worker_map.clear();

// 2. 重新填充
for device in &new_config.devices {
    self.worker_map.insert(device.id.clone(), format!("modbus_worker_{}", device.id));
}

// 3. 清空 pending_requests（如果正在处理的设备请求不存在了）
self.pending_requests.clear();
```

### 5. Worker 重启机制

对于受影响的设备，需要重启对应的 ModbusWorker：

**方案一：发送重连请求**
```rust
context.hub().send(Message::DeviceControl {
    device_id: device_id.clone(),
    operation: Operation::GetStatus,  // 触发连接检查
    params: json!({}),
    correlation_id: next_correlation_id(),
});
```

**方案二：优雅重启**
```rust
// ModbusWorker 接收到配置变化后：
// 1. 完成当前操作队列中的任务
// 2. 断开连接
// 3. 使用新配置重新连接
```

## 📊 错误处理

### 配置解析错误

```rust
match Config::from_file(&config_path) {
    Ok(config) => {
        // 加载成功
    }
    Err(e) => {
        tracing::error!("Failed to load config: {}", e);
        // 保持当前配置，继续运行
    }
}
```

### 热更新错误

```rust
match self.reload_config() {
    Ok(Some((config_json, changed_paths))) => {
        context.hub().send(Message::ConfigUpdate { config: config_json });
        tracing::info!("Config reloaded, changed: {:?}", changed_paths);
    }
    Ok(None) => {
        tracing::debug!("Config file changed but content is the same");
    }
    Err(e) => {
        tracing::error!("Failed to reload config: {}", e);
    }
}
```

## 🎯 优势

- **无需重启**：配置热更新不需要系统重启
- **平滑更新**：设备状态逐步更新，不会造成中断
- **原子性**：设备列表变化是原子的
- **向后兼容**：可以回滚到旧配置
- **智能检测**：内容对比避免不必要的重载
